# الاستضافة المستقلة وربط النطاق

الموقع ثابت بالكامل: ما يُرفع هو محتوى مجلد `dist` فقط (أو ملف `RIWAQ-dist-upload.zip`). لا يحتاج خادم تطبيق أو قاعدة بيانات.

## المضيف المقترح: Cloudflare Pages

يقرأ ملف `_headers` (ترويسات الأمان ومنع الفهرسة)، ويعرض `404.html` تلقائيًا، ويدعم الروابط النظيفة مثل `/projects/`. الرفع ممكن من متصفح الجوال لأنه يقبل ملف ZIP.

### الرفع (بعد موافقتك)

1. أنشئ حسابًا مجانيًا في Cloudflare.
2. من لوحة التحكم: Workers & Pages ← Create application ← تبويب Pages ← Drag and drop your files (أو Upload assets).
3. اختر اسم مشروع، مثل `riwaq-demo`، فيصبح الرابط المؤقت `riwaq-demo.pages.dev`.
4. ارفع `RIWAQ-dist-upload.zip` كما هو، ثم Deploy.
5. افتح الرابط وجرّب: الرئيسية، المشاريع والفلترة، صفحة مشروع والمعرض، طلب التسعيرة حتى النسخ والتنزيل، ثم رابطًا غير موجود للتأكد من ظهور صفحة 404.

ملاحظات:

- حد الرفع بالسحب والإفلات 1000 ملف و25 MB للملف الواحد. النسخة الحالية 51 ملفًا (نحو 3.4 MB) وأكبرها أقل من 0.4 MB.
- المشروع المنشأ بالرفع المباشر لا يتحول لاحقًا إلى ربط Git. إن أردت نشرًا تلقائيًا من GitHub، أنشئ مشروعًا جديدًا مربوطًا بالمستودع، بأمر البناء `npm run build` ومجلد الإخراج `dist`.
- التحديث: أعد البناء ثم ارفع ZIP الجديد من صفحة المشروع (Create new deployment).
- رابط `pages.dev` عام لمن يعرفه. وضع النموذج التجريبي يمنع الفهرسة في محركات البحث، لكنه لا يحجب الزيارة.

## ربط نطاق (بعد موافقتك على النطاق النهائي)

1. اشترِ النطاق أو استخدم نطاقًا تملكه.
2. في مشروع Pages: Custom domains ← Set up a domain ← اكتب النطاق.
   - **نطاق رئيسي** مثل `example.sa`: يجب نقل خوادم الأسماء (Nameservers) إلى Cloudflare من لوحة مسجّل النطاق، وبعدها يُنشأ السجل تلقائيًا.
   - **نطاق فرعي** مثل `www.example.sa`: أضف سجل CNAME لدى مزوّد DNS يشير إلى `riwaq-demo.pages.dev`.
   - أضف النطاق في لوحة Pages **قبل** إنشاء سجل CNAME؛ العكس يسبب خطأ 522.
3. انتظر تفعيل شهادة HTTPS (عادة دقائق، وقد تصل لساعات).
4. أعد البناء بالنطاق النهائي حتى تُضاف روابط canonical وog:url وsitemap:

   ```bash
   SITE_ORIGIN=https://www.example.sa npm run build
   ```

   أو عدّل `origin` في `src/config.js`. ثم ارفع ZIP الجديد.
5. افحص الترويسات الفعلية بعد النشر (من أدوات المطور أو موقع فحص ترويسات).

## قبل فتح الموقع للفهرسة

لا تغيّر `demo: false` إلا بعد استبدال الهوية والصور والمشاريع ببيانات شركة حقيقية موافق عليها (انظر `CUSTOMIZATION.md`). عند `demo:false` ووجود `origin` يُكتب `robots.txt` يسمح بالفهرسة ويشير إلى sitemap، وتُزال ترويسة `X-Robots-Tag`.

## بدائل

- **Netlify (Drop)**: يدعم `_headers` و`404.html` بالطريقة نفسها تقريبًا؛ الرفع بسحب مجلد من متصفح حاسوب.
- **GitHub Pages**: يعمل فقط عند النشر على جذر نطاق (مستخدم أو نطاق مخصص)، لأن المسارات مطلقة `/assets/...`. لا يقرأ `_headers`، فلا تُطبق ترويسات الأمان.
