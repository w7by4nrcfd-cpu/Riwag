# دليل التخصيص والبيع

## تخصيص الهوية

عدّل `src/config.js` ثم نفذ `npm run build`:

```js
name: 'اسم الشركة',
englishName: 'COMPANY NAME',
logo: '/assets/company-logo.svg', // null لاستخدام العلامة التجريبية
origin: 'https://example.com', // أو اتركه فارغًا واستخدم SITE_ORIGIN عند البناء
demo: true,
theme: {
 charcoal: '#242622', ivory: '#f5f2eb', sand: '#d7cbb9',
 bronze: '#80694e', stone: '#6b6b62'
},
```

ضع ملف الشعار في `public/assets`. العلامة التجريبية أصلية مرسومة بالكود لكنها ليست علامة مسجلة. لا تستخدم اسمًا أو شعارًا حقيقيًا دون إذن مالكه. `title` و`description` و`nav` قابلة للتحرير أيضًا. النصوص التحريرية الأساسية في `src/views.js` ويمكن إعادة تحريرها عند تغيير اتجاه النشاط؛ الهيكل لا يعتمد على اسم رِواق.

## الاتصال

```js
contact: {
 whatsapp: '9665XXXXXXXX', // استبدل X بأرقام فعلية قبل التفعيل
 phone: '+9665XXXXXXXX',
 email: 'hello@example.com',
 address: 'العنوان الصحيح', city: 'المدينة', hours: 'أوقات العمل الفعلية'
},
serviceAreas: ['المدينة الأولى', 'المدينة الثانية'],
social: [{label: 'Instagram', url: 'https://www.instagram.com/actual-account/'}]
```

هذه صيغة شرح وليست بيانات جاهزة؛ لا تُدخل أرقامًا عشوائية. يجب أن يكون واتساب بصيغة `9665` ثم ثمانية أرقام، دون علامة +. يتعطل رابط إرسال الطلب إذا لم يكن الرقم صحيح الصيغة. تدقيق ملكية الرقم مسؤولية إعداد بيانات العميل.

لا تظهر أزرار الهاتف والبريد وواتساب عندما تكون القيم `null`. الأرقام التجريبية في الاختبارات لا تظهر للزوار.

## الصور والمشاريع والخدمات

لكل أصل بصري ثلاثة ملفات: `asset-640.webp` و`asset-1200.webp` و`asset-1680.webp` في `public/assets` (أو شغّل `scripts/optimize-images.py` على صور `source-assets`). استخدم أسماء جديدة ثابتة، وعدّل قيمة `image` أو `gallery[].asset` في البيانات. أسماء المشاريع، التصنيفات، الوصف، المواد، نطاق العمل ومعرض التفاصيل مستقلة عن المكونات.

معارض التفاصيل الحالية تستخدم الصورة العامة واقتطاعات معلنة منها. عند إضافة أعمال العميل، استبدلها بزوايا أصلية متعددة مع إذن التصوير والنشر. حافظ على النصوص البديلة ومعانيها. خدمات `services[]` لديها اسم وشرح وخيارات وخطوات ورابط إلى تصور مناسب.

المقارنة تستخدم `before` و`majlis`. عند استبدالها بصور قبل وبعد فعلية، وحّد زاوية الكاميرا والاقتصاص، وعدّل وسم المقارنة بعد التأكد من التطابق. لا تعرض الصور المولدة كأعمال العميل.

جميع عبارات «تصور تصميمي» و«غير منفذ» و«نموذج تجريبي» متعمدة؛ استبدلها فقط عندما توجد بيانات ومشاريع فعلية مثبتة. لا يكفي تغيير `demo:false` لإزالة وسوم الحقيقة من كامل المحتوى.

## SEO والإطلاق

الوضع التجريبي يستخدم `noindex, nofollow` وrobots يمنع الفهرسة. بعد موافقة الشركة على المحتوى والهوية والمشاريع وسياسة البيانات، عدّل `origin` إلى النطاق الصحيح و`demo` إلى `false` ثم راجع titles/descriptions والوسوم. لا توجد بيانات LocalBusiness وهمية أو تقييمات Schema مختلقة. أضف بيانات منظمة للشركة فقط بعد توفير بياناتها الحقيقية.

`dist/_headers` (يولده `scripts/build.mjs`) يحتوي سياسة CSP وترويسات أمن مقترحة للمضيفين الذين يدعمون هذا الملف. لا يعني وجوده أن كل مضيف سيطبقه؛ افحص الترويسات الفعلية بعد الاستضافة، واختبر التضمين قبل تضييق `frame-ancestors`.

## إنشاء نسخة لعميل آخر

1. انسخ المشروع إلى مجلد جديد.
2. احذف ربط الاستضافة `.openai/hosting.json` وبيانات Git من النسخة الجديدة قبل تسجيل مشروع مستقل. لا تستعمل معرف المشروع الحالي لعميل آخر.
3. غيّر الهوية وبيانات الشركة والمشاريع والخدمات ومناطق الخدمة.
4. نفذ البناء والاختبارات، ثم مراجعة بصرية على جهاز فعلي.
5. اختر استضافة مستقلة لكل عميل. النشر العام والنطاق النهائي يتطلبان موافقة مالكه.

## ما يحتاجه البيع كنظام استقبال مركزي

النسخة الحالية مناسبة للعرض والمحتوى واستقبال استفسارات عبر مشاركة الطلب. إن أراد العميل لوحة إدارة وحفظ طلبات: أضف نظام دخول خاص للإدارة، API بتحقق خادمي، تخزينًا خاصًا للملفات مع صلاحيات وروابط مؤقتة، حدود طلبات، مدة احتفاظ وحذف، ومراقبة ونسخًا احتياطية. هذه مزايا غير موجودة حاليًا ولا تُسوّق بوصفها منفذة.
